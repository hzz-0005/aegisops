# 自主调查第一批：实现、实测与剩余边界

日期：2026-10-12（北京时间）。实施计划见 `agent-plan-2026-10-12.md`。

## 已实现

现有 LangGraph 新增 `triage → agent_prepare → agent_plan → agent_observe → agent_plan … → agent_report`。模型从事故症状与目录背景开始，依据实际观察选择下一只读工具、更新目录外候选或决定结束。旧确定性图保留为基线，没有重建 Incident、Temporal 或执行器。

- `agent_contracts.py`：严格决策/工具/候选/轨迹契约，拒绝额外字段和写工具。
- `tool_registry.py`：9 个固定只读调用。参数只有工具名、服务和事故告警 ID；租户与时间来自后端快照，目标限于该告警服务及登记直接依赖，不接受任意 URL/SQL/Shell/PromQL/时间/结果上限。
- `agent_loop.py`：计划与工具观察循环。每轮事实摘要采用字段白名单，不传事故标题、注入标签、告警名称、脚本名、目录答案、日志正文、Span自由文本、SQL或凭据。保留事实的时间、来源核验状态和未绑定限制。
- `agent_journal.py` 与迁移 `0026_investigation_agent`：每次外部调用之前保存预留，之后保存决定、输入摘要和哈希、证据 ID/事实、耗时及提供商用量。相同事故版本只有一个账本；活动中断后不重置预算，未完成调用保留结果不明并停止，旧调用无法覆盖恢复后的状态。
- `InvestigationReport.agent_trace`：沿用现有报告/API持久化和版本/成员陈旧检查。中文工作台增加取证原因、实际结果、候选和停止原因。

预算默认 4 次模型、8 次工具、90 秒调查时间，每次网络请求的超时随剩余预算收缩。总时间在调用前后检查；底层同步I/O不是强制进程终止，尚未做故意拖延网络/失联数据库的端到端硬截止测试。Temporal Activity 仍为 2 分钟、最多 3 次尝试；账本让重试不会再次消耗同一版本的模型预算。

模型输出上限至少1000 token，容纳决策、理由和引用；独立报告复核仍使用原配置。无配置/模型故障/结构或引用非法/越权/重复查询/预算耗尽/版本变化均受控停止。工具无数据与失败会反馈模型，不能当成服务健康。

**所有自主模型候选目前都保持 `INCONCLUSIVE`、无主根因、置信度0。** 尚未实现模型候选的独立根因验证器，不能进入执行目录。模型引用与工具权限受校验不等于推理内容全部正确。

第三次故障的阶段结果：`http_activity` 返回请求/5xx增量；`error_logs` 无数据；`dependency_requests` 返回经Span核验的订单→库存 `dependency_transport` 事实；`incoming_requests` 无数据。该Span仍为 `UNBOUND`，不能据此宣布全部事故共同根因。两个窗口峰值不一定同一时刻，不能直接相除算错误率；最后已补提示和测试，避免这种解释。预算停止报告现明确提醒人工核对末轮观测。

这是同一已知机制的开发复验，**不是3个独立盲测案例，不计算根因准确率或能力提升百分比。** 自主循环已取得最小真实运行证据；独立诊断验证、盲测和审批修复闭环未完成。

本轮账本登记44次模型调用预留，成功返回的 `total_tokens` 累计102800；包含故障触发的其他Incident和版本刷新，不能只按上面两条选中报告估算全轮开销。异常响应没有用量的调用不计为零费用，未计算货币成本。

首次健康脚本 `eval/lab-runtime-20261012T064514Z.json` 为false，原因是主机还运行12个其他Compose项目容器，违反该旧脚本的“独占主机”假设；本项目当时API/UI正常、0活动告警、0库存锁等待。没有停止这些其他项目。最终报告将本项目健康与主机独占分开统计。

Ruff、7个核心文件/脚本的mypy、JavaScript语法、Compose解析通过。API和workflow-worker镜像重建部署，DB0026已实际应用。本机缺少的Temporal SDK已补齐。项目主源码仍未跟踪，未创建提交或推送；`.env`保留且未输出秘密。

## 使用

工作台：`http://127.0.0.1:8010/?view=ops`。可查看此次示例事故 `fbce0c53-5830-48b4-acdb-60bf281c7958` 与缺遥测对照 `06d00d6b-6352-4001-a33a-90198d63fe18`。

Compose工作流调查默认使用新Agent；关闭可在本机`.env`设 `AEGISOPS_INVESTIGATION_AGENT_ENABLED=false` 后重建对应容器。旧报告不会因为重新读取而重新调用模型。新故障及版本更新可产生新调查并消耗模型额度；每版本仍受预算约束。

```powershell
.\.venv\Scripts\python.exe -m scripts.verify_agent_journal
# 以下调用真实模型；第一个会停止并恢复本项目库存服务。
.\.venv\Scripts\python.exe -m scripts.evaluate_agent_live --case inventory-unavailable
.\.venv\Scripts\python.exe -m scripts.evaluate_agent_live --case missing-telemetry
```

## 下一批

1. 先提高有效观测与结论质量：明确各Span工具支持的失败码、服务范围和缺样本覆盖；用阶段预算为最后观察的总结留出机会，而不是无限增加模型调用或样本数。
2. 为目录外候选设计独立证据验证契约，保留支持/冲突、告警来源绑定、历史/当前和覆盖边界。不得把模型候选文字转为SUPPORTED或修复动作。
3. 按真实调查暴露的缺口补遥测，尤其上游网关失败码覆盖和来源关联；遇到数据库事故才补会话/阻塞身份，避免回到无限数据库审计。
4. 冻结独立盲测输入与真值，与确定性基线使用相同成员全集；完成后再复用Plan→OPA→Approval→Attempt→Recovery验证自主调查到受治理修复链路。
5. 故意拖延/中断网络与数据库的硬截止、真实Activity中断恢复、浏览器页面视觉验收仍待补；外部环境未提供，P4尚未开始。
